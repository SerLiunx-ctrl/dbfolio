# 1.0.0-alpha.60

## 中文

本版汇总 alpha.57～60 的改动，新增达梦 DM8 支持，并完善脚本导入、DDL 与操作通知。

- **达梦连接与日常操作**：新增原生连接，无需另装数据库客户端。支持模式、表和视图浏览、查询分页、手动事务、数据编辑、建表、字段行内修改、普通索引及外键管理，并接入 ER 图和数据字典。
- **数据类型与导出**：完善精确数值、日期时间、BIT、BLOB/CLOB 的读取、绑定和预览。普通 CSV/JSON/Excel 导出改为读取完整字段，保留筛选和排序；达梦读取完整大字段，其他适配器遇到截断值会停止导出，避免静默保存部分数据。
- **SQL 文件导入**：达梦沿用文件、编码、预检、执行与报告工作区。完整预检后执行固定快照，提供进度、取消和逐条结果；区分 DIsql 客户端指令与服务器 SQL，保留完整触发器、程序块及独立 / 分隔。
- **查询脚本**：达梦脚本使用同一连接执行，支持完整程序块选择与客户端提示；触发器 :NEW/:OLD 不再被误识别为命名参数。修复查询失败后残留旧结果，以及 MySQL 脚本预检误判合法字段名的问题。
- **原生 DDL**：保留表/视图原生定义中的 IDENTITY、CHECK 和存储选项，补齐独立索引、适用约束及表/字段注释，避免重复创建支撑索引。修复服务器依赖接口返回的部分索引和注释语句无法回放的问题，保留中文、引号和换行。
- **DDL 诊断与编辑器**：原生定义读取失败时显示原因，不再静默使用可能缺失属性的通用脚本；部分依赖失败仍保留有效内容，诊断随复制、打开查询和字典导出保留。查询、分析、DDL、建表预览及确认 SQL 共用达梦高亮，保留查询/分析补全；修复表标题重复显示模式名。
- **操作通知**：修复减少、关闭动效或跟随系统减少动态效果时，通知长期不消失的问题；增加手动关闭，保留悬停和键盘聚焦暂停计时。

兼容性与范围：本轮实库验证为 Windows x64、DM8 8.1.4.80、原生兼容模式、SYSDBA 直连。其他版本、普通角色及 SSH/TLS 尚未全面验收。达梦 SQL 文件导入已支持；SQL 转储生成、专属触发器管理、同步、数据生成和可视化执行计划尚未开放。DDL 页面不包含触发器、授权或外部依赖对象，不等同完整备份；旧字典快照需重新采集。

脚本导入默认自动提交，可显式设置自动提交模式并提交事务；脚本结束会回滚未提交事务，已提交或 DDL 隐式提交的修改保留。暂不支持完整 DIsql 交互、变量替换、文件包含、连接切换和保存点。

## English

This release combines the changes from alpha.57 through alpha.60, adding DM8 support and improving script import, DDL, and notifications.

- **DM8 connections and daily workflows**: Added native connections without requiring a separately installed database client. Supports schema/table/view browsing, paginated queries, manual transactions, data editing, table creation, inline column changes, regular indexes, foreign keys, ER diagrams, and the data dictionary.
- **Data types and export**: Improved exact numeric, temporal, BIT, and BLOB/CLOB reading, binding, and previews. Regular CSV/JSON/Excel exports now read full columns while retaining filters and sorting. DM8 reads complete large values; other adapters stop on truncated values instead of silently saving partial data.
- **SQL file import**: DM8 uses the shared file, encoding, preflight, execution, and report workspace. Full preflight produces an immutable execution snapshot with progress, cancellation, and per-statement results. DIsql client directives are separated from server SQL, preserving complete trigger/program blocks and standalone / delimiters.
- **Query scripts**: DM8 scripts run on one connection, with complete program-block selection and client notices. Trigger :NEW/:OLD references no longer prompt for named parameters. Fixed stale results after query failures and MySQL preflight incorrectly rejecting valid column names.
- **Native DDL**: Preserves IDENTITY, CHECK, and storage clauses in native table/view definitions, while adding independent index definitions, applicable constraints, and table/column comments without duplicating backing indexes. Handles dependency APIs that return index or comment SQL unsuitable for replay, preserving Chinese text, quotes, and line breaks.
- **DDL diagnostics and editors**: Native definition failures now show a reason instead of silently using a generic script that could omit attributes. Partial dependency failures retain available content and diagnostics when copying SQL, opening query tabs, or exporting dictionaries. Query, analysis, DDL, table-creation, and confirmation editors share DM8 highlighting, retaining query/analysis completion. Fixed repeated schema names in table headings.
- **Notifications**: Fixed notifications remaining indefinitely with reduced, disabled, or system-reduced motion. Added manual dismissal while retaining pause-on-hover and pause-on-focus behavior.

Compatibility and scope: Live verification covered Windows x64, DM8 8.1.4.80 in native compatibility mode, and direct SYSDBA connections. Other versions, regular roles, and SSH/TLS have not been fully verified. DM8 SQL file import is available; SQL dump generation, dedicated trigger management, synchronization, data generation, and visual execution plans remain unavailable. DDL pages exclude triggers, grants, and external dependency objects and are not full backups. Existing dictionary snapshots need to be collected again.

Script import uses autocommit by default; scripts can explicitly change this mode and commit transactions. Uncommitted transactions are rolled back at the end, while committed changes and implicit DDL commits remain. Full interactive DIsql behavior, variable substitution, file includes, connection switching, and savepoints are not supported.
