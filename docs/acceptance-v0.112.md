# v0.112 本地文本模板

在数据生成的字段规则中，选择“文本模板”，点击规则参数即可选择常用模板、在光标处插入变量。选区存在时，插入会替换选中文字。

| 场景 | 模板 |
| --- | --- |
| Redis 用户缓存键 | `system:user:{uuid}` |
| 同批次带连续编号 | `test:{run_id}:{n:6}` |
| 日期与唯一标识 | `ORD-{date:yyyyMMdd}-{uuid32}` |
| 自定义前缀 | `${prefix}:{uuid}` |
| 随机后缀 | `sample:{alnum:12}` |

- Redis key 使用本地文本模板，value 使用 AI 生成内容，点击“AI 直接生成数据”会保留 key 规则。
- `{uuid}` / `{uuid32}` 每行不同，同一行各文本字段相同；生成新任务时重新取值，不受随机种子影响。
- `{run_id}` 在同一任务内固定，`{n}` 从 1 开始连续编号；跨 AI 请求批次不会重置。
- `{seeded_uuid}`、独立的“UUID（按种子复现）”、随机整数和随机字符串受种子影响。重复运行相同方案可能重复；短随机串不保证唯一。
- 时间戳和日期固定为任务开始时刻，采用 UTC。日期支持 yyyyMMdd、yyyy-MM-dd、HHmmss、yyyyMMddHHmmss。
- 参数 `${prefix}` 从“方案参数”中读取；未设置时报错。参数值不会再次作为模板解释，未知 `{名称}` 保留字面量，可用于 Redis hash tag。
- 预览、导出和写入使用同一份冻结结果。Redis 仍不覆盖已有键；若生成时发现重复，仍明确报错。

建议自行验证：选择用户缓存模板，生成数条记录，确认 key 已展开而非包含 `{uuid}`；保持种子不变重新生成，确认 key 已改变；保存/加载模板后检查规则仍正确。旧方案不会自动替换为新默认键。
