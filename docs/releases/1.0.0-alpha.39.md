# DBFolio 1.0.0-alpha.39

## 中文

- 补上 Windows 锁屏/安全桌面下当前数据页仍被视为活动页的缺口。清洁的关系型数据网格转入资源回收流程，查询编辑器/结果网格释放渲染组件，并使用 WebView2 低内存目标；解锁后恢复正常目标和页面。未提交修改、无效输入、手动事务和后台任务不自动丢弃、提交或重放，不暂停整个 JavaScript 引擎。
- 增加原生 WebView ProcessFailed 诊断，记录版本、进程异常类别、原因与退出码。渲染进程退出时提供不依赖网页的恢复确认，不静默刷新。用户确认重新加载可能失去未保存编辑，需核对事务与任务状态。
- 本版修补已确认的锁屏资源释放缺口；实际长时间锁屏 OOM 的精确分配源仍未定位，须继续复测，不能视为已证明彻底根治。

## English

- Addressed a gap where Windows lock/secure-desktop transitions left the current data page active. Clean relational grids enter resource reclamation, query editors/results release rendering components, and WebView2 receives a low memory target. Unlocking restores normal behavior. Pending/invalid edits, manual transactions, and background jobs are not automatically discarded, committed, or replayed. The JavaScript engine is not globally suspended.
- Added native WebView ProcessFailed diagnostics recording app version, failure kind, reason, and exit code. Renderer exits offer a native recovery confirmation instead of silently refreshing. Reloading may lose unsaved edits; transaction and task state must be checked.
- This addresses the confirmed lock-time resource reclamation gap. The precise allocation source behind prolonged-lock OOM remains unconfirmed and requires further testing; a complete resolution is not yet established.
