# 1.0.0-alpha.56

## 中文

- 修复 MySQL SQL 文件中 BIT 值可能被导出成奇数位十六进制字面量、导致重新导入报语法错误的问题；改为明确的位字面量，保留 NULL 与 64 位边界值。
- 修复 FLOAT 文本输出有效位不足导致重导入数值变化；补齐空间集合类型别名，按 WKB 与 SRID 保留几何值。
- SQL 文件临时使用兼容模式保留零日期和历史无效日历日期，保留无关严格校验，并在结尾恢复导入连接设置；无法生成完整值时明确报出表/列/类型，避免静默丢值。
- 补充 SQL 文件实际导出、导入和服务器精确值比较的类型往返验收，避免只检查生成文本而遗漏重导入问题。
- 本机 MySQL 8.4.6 覆盖 12 张类型表、29 次导出、51 份 SQL 文件导入和 73 次逐列精确比较，数值、字节及 NULL 均一致；支持本轮验证的单表、整库表数据、分文件及 ZIP 导出方式。
- 本版修复范围为 MySQL SQL 文件。CSV/JSON/XLSX 的截断预览路径和 XLSX 大整数精度问题已记录，尚未修复；其他服务器版本和厂商扩展未据此宣称完成验证。

## English

- Fixed MySQL SQL dumps emitting odd-length hexadecimal literals for BIT values, which caused syntax errors on import. BIT values now use explicit bit literals, preserving NULL and 64-bit boundary values.
- Fixed FLOAT text conversion losing precision on reimport, and recognized the spatial-collection type alias to preserve geometry through WKB and SRID.
- SQL dumps temporarily use a compatibility mode to preserve zero dates and legacy invalid calendar dates while retaining unrelated strict checks, then restore connection settings. Unrepresentable values report the table, column, and type instead of silently losing data.
- Added type round-trip verification using actual SQL export, import, and exact server-side comparisons, covering reimport behavior beyond generated-text assertions.
- Verified 12 type tables, 29 exports, 51 SQL-file imports, and 73 exact per-column comparisons on local MySQL 8.4.6, with matching numeric values, bytes, and NULLs. The tested paths include single-table exports, database table data, split files, and ZIP archives.
- This release fixes MySQL SQL files. The truncated-preview export path for CSV/JSON/XLSX and large-integer precision in XLSX remain known issues. Other server versions and vendor extensions are not claimed as verified by these results.
