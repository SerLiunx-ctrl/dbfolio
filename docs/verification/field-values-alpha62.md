日期：2026-11-17；状态：本轮范围已交付；尚未提交/公开发布。

## 已复现的缺陷

本机 MySQL 8.4.6、STRICT_TRANS_TABLES，使用 alpha.61 正式 EXE、新启动配置与随机 `dbfolio_grid62_*` 测试库。未使用业务表。

- BIT(1)：旧值为整数 0、新值为文本 `"1"` 时，真实 grid_commit 报与用户相同的 Data too long；相同输入换成数值或真实位字节的对照组成功。
- BIT(8/64)：文本 `"0"` 还可能静默写成 ASCII 48，不能只以“提交没报错”判断类型正确。
- BIT 原值为字节时，WHERE 的比较参数也不正确，可报整数/浮点转换错误。仅修 SET 不足以覆盖现有数据、位主键及删除。
- TIME 负值写入服务器正确，旧解码却丢失负号，导致下一次旧值比较失败。
- JSON 旧值比较没有把字符串参数转换为 JSON，后续更新匹配 0 行；旧事务接口未逐条检查匹配数，会产生假成功。
- 原始基线 118 次更新中 104 次精确回读通过。YEAR 的零年显示与非法 TIME 极限测试输入已单独纠正，不将测试期望错误计为产品缺陷。

旧包证据：.qa/alpha62-mysql-grid-native-1794886244653/result.json（精确复现），.qa/alpha62-mysql-grid-native-1794886462266/result.json（类型矩阵）。测试库、会话和进程均已清理。

## 本轮修复与类型范围

| 类型/流程 | 本轮处理 | 验证方式 |
|---|---|---|
| MySQL/MariaDB BIT(1～64) | 元数据为对应位宽的无符号整数；精确读取；新值、原值、键条件统一按实际服务器类型归一；兼容旧大端字节，拒绝越界及空字节猜值 | 生产 Rust 断言、三入口 UI、MySQL 实库矩阵 |
| TINYINT(1)、各整数与 unsigned | 显示宽度不等于布尔约束；完整整数位宽与范围，不经浮点数承载大整数 | 纯解析、MySQL 边界写入回读 |
| YEAR | 仅接受 0 或 1901～2155，避免两位年份被服务器改写 | 前后端范围与 MySQL 回读 |
| TIME(6) | 保留负号、超过24小时的时长和微秒 | MySqlTime 生产解码、MySQL 多轮写入回读 |
| DECIMAL/NUMERIC | 精确文本；受约束的精度/scale/unsigned 拒绝静默舍入；SQLite 声明精度不是约束；保留 PG 负 scale 文本判断 | 纯解析、UI、MySQL DECIMAL(38,18)/(65,30) |
| JSON | 行内/详情/粘贴验证语法但保留原文；原生 JSON 参数显式 CAST，MariaDB LONGTEXT 不误用 CAST；预览与全文读取保留服务器 JSON 文本 | 三入口与 MySQL 多轮精确回读 |
| BINARY/VARBINARY/BLOB | 统一完整偶数十六进制字节，保留空 BLOB；不把不完整字节当普通文本 | 解析、MySQL HEX/NULL 比对 |
| ENUM/SET、字符、DATE/DATETIME | 对合法值做真实写入和服务器值比对，不扩大为任意特殊类型均可编辑 | MySQL 类型矩阵 |
| 新增/更新/删除/单元格详情 | 赋值、原值并发比较及主键共用实际类型；逐条匹配数为1，否则整批回滚 | 生产 SQL 构造、实库 stale/no-op/批次回滚 |
| 未能解码的非 NULL 值 | 明确只读，不默默显示为 NULL 再写回 | 生产分支断言；未宣称空间等扩展类型新增可编辑 |

前端纯测试：scripts/check-grid-field-values.cjs，2671 条断言；三入口和兼容性 UI：scripts/check-grid-field-values-ui.cjs，6 组。后端窄生产测试：scripts/check-mysql-grid-values.cjs，16 组，使用现有 release 依赖编译生产源码，不以自制 SQL 替代真实构造函数。

## 边界

- PG、SQLite、达梦同名 BIT 不按 MySQL 的无符号整数推断；兼容性组件测试不冒充各引擎全量实库验收。
- 这里测试的是数据库数据页写入及对应后端路径，不把此前 SQL 文件导出修复当作编辑已通过。
- ENUM/SET 元数据枚举选项大小写与含逗号解析仍有既有局限，本轮验证其合法文本的参数绑定，不声称重做结构枚举编辑。
- 既有非法日期、厂商扩展和未验证服务器版本不因本轮普通类型矩阵而宣称全部支持。
- 本轮事务冲突与整批回滚实测使用 InnoDB；MyISAM/MEMORY 等非事务表不能保证回滚，现有网格尚未按存储引擎拦截该能力，不将本轮结论推广到非事务表。
- PG NUMERIC 精度大于255时，既有 canonical 的 u8 精度字段无法承载，不能使用本轮 Decimal 精度校验保证防舍入；该模型扩展另行处理。
- 不推断历史错误 BIT 值的原意，不自动改写已有业务数据；实际用户修改继续使用待提交和并发校验流程。
