# DBFolio 1.0.0-alpha.49

## 中文

本次相对上一公开版本 **1.0.0-alpha.43**，汇总 alpha.44～49 的改动。

- **AI 服务配置：** 改为可搜索的模型列表，通过操作按钮和弹窗新增、编辑、测试、设为默认或删除。模型 ID 优先从服务获取，失败或空列表时支持手填；增加思考等级、温度和 Top P，输出 token 配置上限提高到 128000。实际参数及额度取决于服务与模型，旧配置和密钥保留。
- **数据字典：** 新增统一标签页，按表/视图范围采集结构，支持表与字段搜索、业务分组、缺少说明筛选，以及字段、索引、外键、对象定义查看和结构跳转。对象/字段本地说明与数据库注释分别保留，不修改数据库；支持保存/废弃、Ctrl+S、列宽调整和 Markdown、HTML、Excel 导出，失败对象明确标记。
- **MariaDB 首批兼容：** 共用 MySQL / MariaDB 连接入口并自动识别服务器，按版本提供 UUID、IP、JSON、向量等类型。修复隐藏列等厂商扩展影响普通列编辑、JSON CHECK 顺序和改名引用、存储引擎列表及元数据语句分页问题；保留默认值、生成表达式和校验定义，保护特殊索引，向量 SQL 导出使用二进制保真。同步要求同厂商，阻止 MySQL 与 MariaDB 混合同步。
- **消息系统首批：** 新增 Kafka、RabbitMQ、RocketMQ 会话及共用工作区，支持对象搜索、范围预览、消息详情、测试发送、基础管理和诊断。Kafka 使用原生协议，RabbitMQ 使用 Management API，RocketMQ 使用 Dashboard 2.x；所需服务入口请参阅[支持范围](https://github.com/SerLiunx-ctrl/dbfolio/blob/v1.0.0-alpha.49/docs/message-queues.md)。
- **消息读取与保护：** 区分文本、二进制和空值，精确显示 Offset，支持 Ctrl+F 查找已加载消息及 JSON/JSONL 导出，限制读取容量并释放后台预览。RabbitMQ 取样会取出后重新入队，需确认且只读会话禁止；写入结果不确定时提示核对，不自动重试。Kafka 消费组管理、持续跟随和高级消息类型未开放，完整认证/TLS 部署矩阵仍待补验。
- **视图适配：** 视图使用独立页签图标；普通视图隐藏不适用的索引、外键、网格写入、触发器和数据生成入口，结构页只读展示结果列，信息页隐藏无效表属性。物化视图或实际返回的索引仍可查看；缺少定义时不伪造建表 SQL。后端同时阻止视图网格预览/提交，查询页显式 SQL 保留。
- **对象树快捷按钮：** 每个关系型数据库右侧增加显示/隐藏视图、刷新对象、新建查询。显隐按会话和数据库保存，仅作用于对象树，不关闭已打开的页签；快捷按钮不会选中或折叠数据库。
- **ER 图：** 取消点击表/关联后的右侧详情栏，详情和原操作附着在对应表卡片下方展开，保留字段跳转、规则、AI 依据及本地标注删除。来源表被隐藏时仍可从画布内信息卡操作；长详情独立滚动。PK/FK/BK 加强标识，选择关联线时高亮两端全部对应字段，支持复合关系；BK 仅表示本地业务标注。
- **验证与保留项：** MySQL 8.4.6、MariaDB 11.8.9、SQLite 及三个隔离消息服务的相应功能实测、三引擎/三主题/双缩放界面、正式包启动/资源/签名检查通过。PostgreSQL 实库验收依约保留，元数据重建定义不能替代备份。完整旧版到新版安装/便携升级及持续锁屏识别仍待验收，不宣称长时间锁屏 OOM 已根治。ER 布局、快捷键及新视图显隐等偏好尚未全面纳入跨设备配置迁移。

## English

This release includes changes from alpha.44–49 relative to the previous public release, **1.0.0-alpha.43**.

- **AI configuration:** Manage models in a searchable list with action buttons and dialogs for creating, editing, testing, setting the default and deleting. Model IDs are fetched from providers, with manual entry on failure or empty results. Added reasoning effort, temperature and Top P, and raised the configurable output-token cap to 128000. Actual parameters and limits depend on the provider/model; existing settings and credentials are retained.
- **Data Dictionary:** A shared tab collects scoped table/view metadata with table/field search, business groups, missing-description filters, columns, indexes, foreign keys, definitions and structure navigation. Local descriptions remain separate from database comments without modifying the database. Includes Save/Discard, Ctrl+S, resizable columns and Markdown/HTML/Excel export with explicit failed-object reporting.
- **Initial MariaDB support:** A shared MySQL / MariaDB connection option identifies the server and offers version-aware UUID, IP, JSON and vector types. Fixed ordinary column editing with vendor extensions such as invisible columns, JSON CHECK ordering and renamed references, engine lists and metadata-statement pagination. Preserves defaults, generated expressions and checks; protects special indexes and exports vectors as binary SQL literals. Synchronization requires the same server family and rejects mixed MySQL/MariaDB endpoints.
- **Initial messaging support:** Added Kafka, RabbitMQ and RocketMQ sessions and a shared workspace for object search, bounded previews, details, test publishing, basic management and diagnostics. Kafka uses its native protocol, RabbitMQ the Management API and RocketMQ Dashboard 2.x. See the [supported scope and service requirements](https://github.com/SerLiunx-ctrl/dbfolio/blob/v1.0.0-alpha.49/docs/message-queues.md).
- **Message handling and protection:** Distinguishes text, binary and null values, preserves exact offsets, supports Ctrl+F on loaded messages and JSON/JSONL export, bounds reads and releases inactive previews. RabbitMQ sampling retrieves and requeues messages, requires confirmation and is blocked in read-only sessions. Uncertain writes require checking the actual result and are not retried automatically. Kafka consumer-group management, continuous following and advanced message types are not available; the full authentication/TLS deployment matrix remains pending.
- **View adaptation:** Views have distinct workspace icons. Ordinary views hide inapplicable indexes, foreign keys, grid writes, triggers and data generation. Structure shows read-only result columns, and Information omits table-only properties. Materialized views or actual returned indexes remain inspectable. Missing definitions do not generate fabricated CREATE TABLE statements. The backend also rejects view grid previews/commits while explicit SQL remains available in the query editor.
- **Explorer shortcuts:** Right-aligned relational database buttons show/hide views, refresh objects and open queries. Visibility is stored per session/database and affects the explorer only, without closing open tabs. Shortcut clicks do not select or collapse a database.
- **ER diagrams:** Details and existing actions expand beneath the corresponding table card instead of opening a right sidebar. Field navigation, rules, AI rationale and local annotation deletion remain available. Hidden source tables retain an on-canvas information card, and long details scroll independently. Prominent PK/FK/BK labels and endpoint highlighting include all fields of composite relationships; BK denotes local business annotations only.
- **Validation and remaining limits:** Relevant workflows passed against MySQL 8.4.6, MariaDB 11.8.9, SQLite and three isolated messaging services, alongside three-engine/theme/zoom UI and formal package startup/resource/signature checks. Live PostgreSQL acceptance remains deferred as agreed. Reconstructed definitions do not replace backups. Complete old-to-new installer/portable upgrade acceptance and sustained lock-state detection remain pending; prolonged-lock OOM is not considered fully resolved. ER layouts, shortcuts and preferences such as view visibility are not yet fully included in cross-device configuration migration.
