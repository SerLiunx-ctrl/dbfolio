# alpha.57 操作通知生命周期验收

日期：2026-11-11；版本：1.0.0-alpha.57；状态：本轮范围已交付，尚未提交/公开发布。

## 根因与修复

- 全局操作通知共用 `AppToaster/useNotify`，原来已经设置成功 3000 ms、错误/取消 6000 ms 超时，并非未设置消失时间。
- 当前 Fluent Toast 内部通过不可见 `span[data-timer-status]` 的 CSS `animationend` 触发到期关闭；`motion.css` 的减弱、关闭及系统减少动态效果规则使用 `animation:none!important`，把该功能计时器同时停掉。
- 使用 alpha.56 标签中的原始动效样式加载真实组件复现：完整模式到期后 0 条，减弱与关闭模式 7.6 秒后仍各留 2 条，计时器计算样式变成 `animation-name:none; animation-duration:0s`。证据：`.qa/toast57-baseline.json`。
- 修复动效规则，保留不可见功能计时动画；普通视觉动画继续遵守原偏好，不强制恢复视觉动效。成功、错误和取消提示统一增加带中文辅助名称的小号关闭图标；保留组件原有悬停、键盘焦点暂停及离开恢复。

## 专项验证

- `scripts/check-toast-lifecycle.cjs` 实际加载生产通知组件与全局样式：深浅两种主题 × 完整/减弱/关闭/系统减少动态效果共 8 组，成功提示到期移除、错误提示保留至对应超时并移除，全部通过。
- 交互专项通过：悬停超过 3 秒不消失、移开恢复、键盘焦点暂停和移出恢复、后台到期、手动关闭、取消提示、多条通知单独关闭，以及已显示通知期间切换动效。没有页面异常；共 9 组，结果 `.qa/toast57-lifecycle.json`。
- 原动效设置回归通过：完整/关闭视觉行为、保存重载、跟随系统减少动态效果和系统偏好变化。修正原脚本误选同名主题“跟随系统”单选项的定位，按包含“完整”选项的动效组定位，不将测试定位失败归因于产品。
- 本轮不改变数据库、任务、连接状态或错误处理；通知共用组件覆盖所有调用引擎，不需要分别修改 MySQL、SQLite 等适配器。
