## alpha.16 启动修复（2026-10-22 已验收）

- 已实际复现 alpha.15 正常启动退出，错误为 `PluginInitialization("updater", "Error deserializing plugins.updater ... invalid type: null, expected struct Config")`。原因是公钥仅在 Rust Builder 与安装器临时配置中提供，插件先反序列化运行时配置、后才应用 Builder 的公钥，因而在窗口和数据初始化之前崩溃。
- 修复为检入完整的插件配置，正式编译、开发和安装器直接共用。新增配置回归检查：反序列化实际插件 Config，核对公钥与仓库公钥文件一致，HTTPS/证书/降级保护未关闭。
- 完整 Rust 回归 157 项通过、18 项默认跳过；前端 TypeScript 与生产构建通过。新增 `check-app-startup.ps1` 使用全新 SQLite 配置目录和 WebView2 缓存，正常进入 Tauri 和所有插件，要求主窗口可见、前端 IPC 就绪且进程持续运行；仅关闭自己启动的检查进程。
- 负向验收已确认：该脚本会拒绝 alpha.15，捕获同一真实插件崩溃；之前的 `--verify-resources` 与 `--apply-update` 只验证资源或辅助进程，绕过正常启动链路，不能充当应用可打开的证据。
- 正式 `npm run app:build` 成功，LTO 编译 15 分 27 秒；打包阶段、最终 portable、NSIS 解包 EXE 均确认主窗口可见和前端 IPC 就绪。资源自检与签名产物专项另行通过。一次 portable 检查在关闭时超过 8 秒、由脚本结束自己的检查进程；随后使用两个全新目录连续复查，均正常启动并以退出码 0 关闭。该超时原因未确定，不把它记作正常退出，也不据此夸大为已复现应用启动异常。
