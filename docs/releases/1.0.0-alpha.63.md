# 1.0.0-alpha.63

## 中文

本次公开版本汇总 alpha.61～alpha.63 的更新，重点改进数据编辑、复制粘贴和右键操作。

- 新增“复制为 INSERT / UPDATE 语句”：数据页使用当前表，查询结果可选择实际目标表，预览后复制 SQL。UPDATE 根据完整、非空的主键定位记录。
- 行复制保留换行、Tab 和引号；软件内复制的行还保留 NULL、空字符串、大整数、Decimal 和二进制值。修复单元格引号被剥离，以及 SQLite 空 BLOB 被误当作 NULL 的问题。
- 数据页支持“复制为新行”和“粘贴为新行”，无主键表也可新增记录。Ctrl+V / 工具栏粘贴会将软件内复制的行追加为新行，外部文本从当前单元格覆盖；新增内容进入待提交，确认后写入，并略过自增及已识别的生成列。
- 数据页与查询结果统一使用紧凑的二级右键菜单：“复制”“复制 SQL”“粘贴”按用途分组，常用查看、关联、筛选和修改操作保留在第一层。支持鼠标悬停、方向键、逐级 Esc 关闭及窗口边缘自动翻转，多选和空白处右键操作保持可用。
- 修复 MySQL BIT(1) 编辑时报 Data too long，以及位字段文本可能被写成 ASCII 数值的问题。BIT(1～64) 按实际位宽精确读取、校验和写入，覆盖新增、修改、主键条件、旧值比较及删除。
- 修复 MySQL TIME 负值和超过 24 小时时长的回读，保留微秒；YEAR 接受 0 或 1901～2155，避免年份自动转换；TINYINT(1) 按整数范围处理，显示宽度不再被误当作布尔约束。
- 修复 MySQL JSON 连续编辑时旧值比较匹配不到记录的问题。预览和完整读取保留服务器 JSON 原文，避免大整数被客户端重写；MariaDB LONGTEXT 保持对应的文本处理规则。
- 行内编辑、单元格详情和粘贴统一校验整数范围、Decimal 精度与小数位、无符号值、YEAR、JSON 语法和完整十六进制字节。Decimal 输入保留精确文本，超出已知精度或小数位时提示错误，避免静默舍入；SQLite 数值亲和遵循其自身规则。
- 提交时逐条核对匹配行数。事务表遇到并发冲突或异常匹配时整批回滚，并保留待提交修改，方便核对后重试。

## English

This public release brings together the updates from alpha.61 through alpha.63, focusing on data editing, copy and paste, and context menus.

- Added Copy as INSERT / UPDATE. Table data uses the current table, while query results let you choose an actual target table. Preview the generated SQL before copying it. UPDATE identifies records using a complete, non-null primary key.
- Row copying preserves embedded line breaks, tabs, and quotes. Rows copied within the application also retain NULL, empty strings, large integers, Decimal, and binary values. Fixed cell quotes being stripped and SQLite empty BLOBs being mistaken for NULL.
- Table data supports Duplicate as New Rows and Paste as New Rows, including insertion into tables without primary keys. Ctrl+V and toolbar paste append internally copied rows; external text overwrites from the current cell. New rows remain pending until confirmed, with auto-increment and identified generated columns omitted.
- Table data and query results now share compact, two-level context menus. Copy, Copy SQL, and Paste are grouped into submenus, with common inspection, relationship, filtering, and editing actions at the first level. Menus support hover, arrow keys, level-by-level Escape, and automatic flipping at window edges, while preserving multi-selection and blank-area context menus.
- Fixed Data too long when editing MySQL BIT(1), and text values potentially being stored as ASCII numbers in bit fields. BIT(1–64) now uses exact values validated against the actual bit width for inserts, edits, primary-key conditions, previous-value comparisons, and deletion.
- Fixed reading negative MySQL TIME values and durations over 24 hours while preserving microseconds. YEAR accepts 0 or 1901–2155 to avoid automatic year conversion. TINYINT(1) uses its integer range rather than treating display width as a boolean constraint.
- Fixed previous-value comparisons failing to find records during successive MySQL JSON edits. Preview and full-value reads preserve server JSON text so large integers are not rewritten by the client. MariaDB LONGTEXT retains its appropriate text handling.
- Inline editing, cell details, and paste share validation for integer ranges, Decimal precision and scale, unsigned values, YEAR, JSON syntax, and complete hexadecimal bytes. Decimal input retains exact text and reports values exceeding known precision or scale instead of silently rounding them. SQLite numeric affinity follows its own rules.
- Submissions verify the matched row count for each statement. On transactional tables, concurrent conflicts or unexpected matches roll back the entire batch and retain pending edits for review and retry.
