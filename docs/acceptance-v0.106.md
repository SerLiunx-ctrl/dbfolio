# v0.106 数据生成 G1–G3：使用与自行验收

## 开始使用

1. 在「设置 → AI 服务」填写兼容 OpenAI 的 Base URL（通常以 `/v1` 结尾）与密钥，点击「获取模型列表」，选择模型、测试并保存。无模型列表的服务可手动填写 ID。本地规则生成无需 AI 配置。
2. 从表右键「生成测试数据」、表/集合/Redis 工具栏「数据生成」，或底部工作区菜单打开生成页签；Ctrl+P 输入 `> 数据生成` 也可进入。
3. 选择目标并读取结构，在「规则与模板」调整字段。先用少量数据预览，再扩大数量；生成本身不写库。
4. 检查冻结批次。可导出，或点击「确认写入」，核对会话、环境、库/对象和条数后提交。

## 自行验收清单

请使用测试库、测试集合与专用 Redis 键前缀。运行文件为 `release/Data Workbench v0.106.exe`。本轮未控制桌面进行验收。

| 项目 | 操作 | 预期 |
| --- | --- | --- |
| AI 配置 | 新增两个服务、设置默认、保存并重新进入 | 模型和参数保留，密钥仅显示“已保存”，可保持/替换/移除；默认服务有标记 |
| 模型/连通性 | 获取列表、手动模型、错误密钥/路径 | 可选择列表模型；不提供列表时仍能手填；错误有中文提示且不显示密钥 |
| 协议兼容 | 切换 JSON/普通文本；按服务要求选择 max_tokens 或 max_completion_tokens | 测试和实际请求使用选定参数；不支持格式时提示调整，不自动反复请求 |
| SQL 本地生成 | 测试表的自增列省略，唯一列用序列/文本 `{n}`；生成 205 条 | 50 条/页；预览不改变表；确认后分为 100/100/5 三批；新增数正确 |
| 值语义 | 同时配置 NULL、空文本 `""`、省略、JSON、大整数字符串 | NULL、空文本和省略可区分；大整数不经过 JS 浮点数；不安全 JSON 数字会提示改用字符串 |
| 校验 | 重复唯一值、过长文本、超范围整数、小数超精度、错误计算依赖 | 生成失败不产生可写入批次，显示具体字段/原因；循环引用被拒绝 |
| 模板 | 保存/更新/复制/删除、JSON 导入导出、选择多字段批量改规则 | 规则参数独立，模板按引擎过滤；模板文件不包含连接信息或密钥；应用后可继续编辑 |
| 方案参数 | 文本用 `qa:${prefix}:{n}`，参数设置 `prefix` | 每行替换参数和行号；未配置参数时报错，不作为脚本执行 |
| 草稿恢复 | 配置生成页签，退出/重开并重新连接 | 目标、规则、数量、种子、参数和 AI 引用恢复；不会恢复或自动提交旧批次 |
| AI 规则建议 | 输入业务要求，点击建议，先取消再确认应用 | 先展示建议与实际 token 用量；取消不覆盖；应用后可修改和生成 |
| AI 内容 | 将 1–2 个文本字段设为 AI 内容，生成 12 条 | 两次请求（每批最多 10 条），本地字段保持关联；返回错误条数、字段或类型时拒绝批次；确认写入不再次调用 AI |
| MongoDB | 已有测试集合中配置 `_id` ObjectId、`profile.name`、整数/小数/日期规则 | 预览保留 EJSON；写入为嵌套文档、Int64、Decimal128、UTC Date；集合验证器不满足时停止 |
| Redis | String 与 Hash 分别生成，使用专用 `qa:` 前缀与 TTL | 新键创建并带 TTL；再次生成相同键，明确失败且原值不被覆盖；Hash value 为字符串值对象 |
| 提交保护 | 对已提交批次再次操作；生成后改目标结构或连接配置 | 批次不允许重复提交；目标变化要求重新生成；只读会话可导出不能写入 |
| 取消/部分失败 | 大任务中取消；让第二个 SQL 批次与已有唯一值冲突 | 已提交批次保留，后续停止；分别显示已提交/明确失败/待核对/未尝试数量；不自动重试 |
| 导出 | 导出 JSON/JSONL/CSV；取消大导出 | 导出完整冻结批次；取消不破坏原文件；MongoDB 仅 JSON/JSONL 保留 BSON 类型 |
| 布局与主题 | 窄工作区、高缩放、深浅主题、字段参数/二级确认弹窗 | 字段表/预览与弹窗内部滚动，标题及操作可达，主题一致；不会强行撑高整个窗口 |

## 已完成的后台验证

- Rust 自动测试 49 项通过（4 项需显式环境的测试默认跳过；本轮另外运行了其中的本机生成集成测试）：隔离 SQLite 生成、冻结分页/导出、精度、结构变化、唯一校验、重复提交、只读、批次失败回滚、取消；模拟 HTTP 的模型列表/认证/输出/错误脱敏/取消，以及 AI 字段冻结。
- 本机集成测试：MySQL 和 PostgreSQL 各 205 条，包含默认时间戳覆盖与 JSON 字符串值；MongoDB 12 条含嵌套字段和 BSON 精度/日期类型；Redis String/Hash 原子创建、TTL、已有键拒绝。随机测试对象均已清理，没有读写业务记录。
- 前端回归：模板并发保存/失败恢复、字段规则独立性、生成方案和页签重启恢复、原有工作区/连接/任务回归。TypeScript/Vite 构建通过。
- 未验证：用户自配的真实 AI 服务（需要用户提供接口和密钥）、桌面实际视觉与拖动体验。AI 测试按钮和生成操作可能由用户的供应商计费。

## 首轮边界

- 每次 10 万条、64 MiB；含 AI 内容时最多 2000 条。缓存最多 8 批次 / 128 MiB，关闭不用的生成页签释放；AI 与本地生成分别最多两个并行任务。
- SQL 未知类型、二进制、向量写入未开放；非 InnoDB 的 MySQL 表只支持预览导出。外键值需手动指定已有合法值，不自动采样业务表。
- MongoDB 目标集合需存在；完整验证器/唯一索引以服务端为准。Redis 仅 String/Hash，需允许 EVAL。MongoDB/Redis 逐条提交，不提供整批回滚。
- 计算仅拼接、整数加法/乘法；小数最多 12 位小数。CSV 不保留类型，无损数据请选 JSON。
- 网络/超时造成的结果待核对不会自动重试；不要直接重生成相同数据继续提交。多表关系、语义向量、其他 Redis 类型、跨重启断点续写属于 G4，未实现。
