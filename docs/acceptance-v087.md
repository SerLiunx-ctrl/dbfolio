# v0.87 自行验收

本轮只做代码、自动测试和打包，没有控制桌面或连接业务数据库。自行关闭旧版后运行 `release/Data Workbench v0.87.exe`。

## 1. 查询历史中心

- 底栏点击“历史中心”，尝试 SQL 关键字、连接、数据库完整名称、UTC 日期区间、成功/失败筛选及翻页。
- 收藏一条 SQL，勾选“仅收藏”；退出重开确认仍在。
- 保留当前 SQL 未保存修改，再从历史点击“重新打开”：应创建新页签并填入历史 SQL，不自动执行，原编辑保留。

## 2. Ctrl+P 快速打开

- 在编辑器或表格中按 Ctrl+P，输入表名、视图名、页签名、收藏 SQL 或曾打开/保存的 SQL 文件名。
- 对象范围默认当前连接，可切换所有已连接会话；加载过程中本地页签和文件可先用，部分失败会提示。
- 使用 ↑↓、Enter 和 Esc。对已有 SQL 文件页签，应激活原页签而不是重新读取并覆盖未保存内容。
- 打开不同 schema 下的同名表，确认是两个独立页签。Redis 键收藏应进入对应库并定位该键。

## 3. SQL 编辑

- 输入 `SELECT ';' AS marker; SELECT 2 AS result;`，光标放在第二句，按 Ctrl+Enter，应只执行第二句；选区仍优先。
- 点击“格式化”或 Ctrl+Shift+F；引号内原文与注释保持不变，Ctrl+Z 可撤销排版。
- 测试 `SELECT :name AS name, :count AS count, :name AS again;`：同名参数只输入一次；分别尝试文本 `O'Reilly`、数字 `9007199254740993`、布尔和 NULL。实际 SQL 会进入历史，不要用真实密码测试。
- PostgreSQL 的 `col::text` 和字符串/注释中的 `:name` 不应弹出参数输入。
- 在 `SELECT u. FROM public.users AS u` 的 `u.` 后唤起补全（替换为测试库真实表）；尝试 `schema.` 或 MySQL `database.`。

## 4. 筛选

- 对文本 `001`、空字符串、NULL 和数字单元格右键“按此值筛选（替换条件）”。先排序再右键，确认取的是当前显示行。
- 未提交网格修改时筛选应被拦截；截断长文本不能用于精确筛选。
- 在筛选面板添加条件，切换“全部/任一条件”；命名并保存方案，退出重开后载入再应用。
- 不同 schema 同名表的方案隔离；同名保存覆盖当前表方案，删除只影响所选方案。

## 自动验证

前端生产构建与 release-fast 打包通过，发布文件复制后 SHA-256 与构建产物一致。

- `node scripts/check-productivity.cjs`：语句边界、注释/引号/dollar-quote、方言转义、命名参数、别名/schema、格式化保留非空白内容；收藏与方案并发保存、失败恢复和页签隔离。
- 原有 `check-workspace.cjs`、`check-runtime.cjs` 回归；菜单检查 7 个定位场景、49 个菜单图标。
- Rust 本地内存 SQLite：历史筛选在分页之前生效、日期/结果/连接/库过滤、参数绑定；字面量类型/引号/大整数与非法数字检查。默认 Rust 测试 16 项通过，2 项真实数据库测试忽略。
- 桌面交互和真实 MySQL/PostgreSQL/Redis 兼容性由用户自行验收。
