# v0.107：AI 直接生成

## 修复原因

之前的“根据要求建议规则”仅配置生成规则；普通预览只有在字段规则为“AI 生成内容”时才请求模型。因此填写要求后仍可能生成“示例-1”等本地数据。

现在提供独立的“AI 直接生成数据”主按钮，自动选择业务字段并调用模型，成功后进入预览。

## 自行验收

1. 打开数据生成页，选择目标并读取结构。
2. 设置数量，例如 10 条。在 AI 区域选择已配置的服务和模型，填写业务要求；刚添加服务可点“刷新服务列表”。默认服务或唯一服务会自动选中。
3. 检查“AI 生成字段”列表。序列、UUID、ObjectId、计算、默认值、NULL 和 Redis key 等仍按原规则生成；需要调整可在下方字段规则中修改。
4. 点击“AI 直接生成数据”，观察任务进度显示请求行区间。无需先点规则建议或逐个选择 AI 规则。
5. 成功后预览应显示“来源：AI + 本地规则”、实际请求次数及业务内容。生成数量以上方数字设置为准，提示词中的数量不会覆盖它。
6. 数据尚未写入，确认内容后再使用“确认写入…”。导出与写入使用同一份冻结数据。
7. 返回修改规则：本次已选业务字段会保留为 AI 规则。需要恢复纯本地生成可点击“重置建议规则”，再点“按本地规则生成”；预览应显示未调用 AI。
8. “仅建议生成规则…”仍会先展示规则并要求应用；它不会直接生成数据。
9. 清空要求、取消服务选择、将数量设为 2001，分别点击直接生成，应显示明确错误；服务失败或返回不合法内容也应报错，不应显示成功预览。

## 验证与边界

- 前端回归通过：自动选择、原方案隔离、服务/要求/数量/空范围校验、Redis 键保护、MongoDB 自定义字段、模板和草稿恢复。
- 50 项 Rust 测试通过、4 项显式集成测试跳过。模拟兼容 HTTP 服务覆盖调用生成、内容冻结、用量、行号上下文，以及少行、错误字段、错误类型、截断不产生批次；隔离 SQLite 检查无隐式写入。
- 未调用用户的真实计费服务，未操作桌面。实际模型输出质量仍取决于服务、模型和要求；内容生成最多 2000 条，每次请求最多 10 条。
- 自增/默认值等字段不会因直接生成而自动接管；MongoDB 没有验证器的集合需要先添加所需业务字段。外键需自行提供有效引用；现有记录不会自动发送给模型。
