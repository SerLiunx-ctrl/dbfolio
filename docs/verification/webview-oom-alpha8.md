# WebView2 内存溢出修复验收记录

- 日期：2026-09-30
- 版本：v1.0.0-alpha.8
- 问题：Windows 锁屏后返回 DBFolio，界面显示 WebView2 的“此页存在问题 / Out of Memory”。锁屏是否直接触发内存增长尚无证据。

## 崩溃证据

本机两份 WebView2 渲染进程转储的异常码均为 `0xE0000008`（Chromium OOM）。崩溃时渲染进程私有内存约 4.5 GB；操作系统仍有约 7～12 GB 可用物理内存。因此优先控制单个渲染进程长期保留的 UI 与图片资源。转储不包含可直接确认的 React 分配调用栈，不能据此断言唯一根因。

## 回归范围

1. 多个 MySQL、PostgreSQL、SQLite 表页签切换：后台清洁表格卸载网格；30 秒后释放行数据，重新激活恢复当前筛选、排序和页码并重读数据。
2. 表格有未提交的新增、修改或删除时：切到其他页签或结构页，修改仍保留，回到数据页可继续保存或废弃。
3. 查询页签切换：后台卸载 Monaco 与结果网格，SQL 草稿和结果保留；重新激活后仍可编辑、复制和翻页。
4. Base64 图片：多张缩略图串行解码；离开视口的排队任务取消；大于 4000 万像素的图片不在窗口预览，但可导出原图。
5. 静态构建与 Rust 测试；正式 NSIS 安装包、完整 portable 目录和 ZIP，以及两份 SHA256SUMS 完整性校验。

## 验证结果

- `npm run build`：通过。
- `cargo test`：128 项通过，13 项因需要外部服务而跳过，无失败。
- `npm run app:build`：通过；生成 NSIS 安装包、portable 目录和 ZIP，打包时 EXE 对外置 `web/` 完成资源自检。
- SHA256：portable 清单 106 条、setup 清单 1 条，逐条独立重算均无不匹配；ZIP 含 EXE、`web/web-manifest.json`，共 105 个条目。
- 长时锁屏与原始数据库工作负载复现：本次没有可自动复现的环境，需要后续使用观察。
